# AI_REVIEW_CHECKLIST.md

## Назначение

Чек-лист для проверки изменений перед commit/push и deploy. Особенно
обязателен для:

-   onboarding
-   templates
-   seed
-   migrations
-   auth
-   roles/accounts
-   multitenant logic

------------------------------------------------------------------------

## PRE-COMMIT CHECKLIST

### A. Код

-   [ ] git status --short
-   [ ] git diff --stat
-   [ ] Показать список изменённых файлов
-   [ ] Объяснить назначение каждого изменённого файла

### B. Тесты

-   [ ] Целевые тесты проходят
-   [ ] Полный pytest проходит
-   [ ] Smoke-сценарии проходят

### C. Docker

-   [ ] docker compose up -d --build
-   [ ] Контейнер действительно пересобран
-   [ ] Проверка на существующей БД (existing volume)
-   [ ] Проверка на чистой БД (fresh DB), если применимо

### D. API

-   [ ] Проверен фактический ответ API
-   [ ] Ответ соответствует ожиданиям
-   [ ] Нет расхождения между кодом и API

### E. UI

-   [ ] Выполнена визуальная проверка
-   [ ] Проверен пользовательский сценарий
-   [ ] Скриншоты или фактическое описание результата

### F. Source → DB → API → UI

Для шаблонов, seed и onboarding обязательно:

-   [ ] Source bundle count
-   [ ] DB rows count
-   [ ] API preview count
-   [ ] UI preview count

Если значения различаются --- commit запрещён до объяснения причины.

------------------------------------------------------------------------

## TEMPLATE / ONBOARDING AUDIT

Обязательная таблица:

  Источник         Количество
  ---------------- ------------
  Source bundle    
  DB rows          
  API preview      
  Wizard preview   

Проверить:

-   [ ] source == DB
-   [ ] DB == API
-   [ ] API == UI

------------------------------------------------------------------------

## DEPLOY CHECKLIST

Перед deploy:

-   [ ] Commit создан
-   [ ] Push выполнен
-   [ ] Локальная визуальная проверка завершена
-   [ ] Есть план отката
-   [ ] Есть backup БД

После deploy:

-   [ ] Smoke-test выполнен
-   [ ] Основной пользовательский сценарий работает
-   [ ] Нет ошибок в логах

------------------------------------------------------------------------

## Правило проекта

Для инфраструктуры, onboarding, шаблонов и миграций источником истины
считается не отчёт Cursor и не тесты, а подтверждённое совпадение:

Source → DB → API → UI

До визуальной проверки пользователя commit/push/deploy считаются
незавершёнными.
