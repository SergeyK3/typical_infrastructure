# Post-MVP Roadmap

## Назначение

Приоритизация направлений развития после стабилизации MVP. Источник: [mvp_backlog_by_phases.md](mvp_backlog_by_phases.md) §13.

---

## Направления (из §13)

| # | Направление | Краткое описание | Приоритет |
|---|-------------|------------------|-----------|
| 1 | **Расширенный RBAC** | Тонкая настройка прав на уровне операций, ролей | P2 |
| 2 | **Импорт из HR-источников** | Stage-1 профили, внешние HR-системы | P1 |
| 3 | **События и уведомления** | Event bus, webhooks, уведомления | P3 |
| 4 | **Каталог компетенций** | Справочник компетенций, привязка к должностям | P2 |
| 5 | **Assessment / диагностика** | Оценка сотрудников, диагностика | P2 |
| 6 | **Learning plans** | Планы обучения, связь с компетенциями | P2 |
| 7 | **KPI / performance integration** | Интеграция с KPI, performance-метриками | P3 |

> *Предварительная приоритизация. Уточнить по результатам пилота.*

---

## Принцип приоритизации

> Эти направления должны идти **после** стабилизации MVP-ядра onboarding, а не вместо него.

Рекомендуемый порядок определения приоритетов:

1. Собрать обратную связь от пилота (см. [STEP8_FEEDBACK_TEMPLATE.md](STEP8_FEEDBACK_TEMPLATE.md))
2. Выделить наиболее востребованные сценарии
3. Оценить трудозатраты и зависимости
4. Зафиксировать приоритеты в таблице выше
