One-Click Onboarding

Мастер развёртывания типовой инфраструктуры предприятия

1. Типовая инфраструктура

Выберите набор оргструктуры, должностей, KPI и регламентов, который будет развёрнут для новой организации.

2. Данные клиента

Вы создаёте новую организацию на основе выбранной типовой инфраструктуры (шаг 1). Укажите код и название клиента ниже.

Нужно применить шаблон к существующей организации? Перейдите в список клиентов и нажмите «Применить шаблон» на карточке организации.

3. Оргструктура (предпросмотр)

Структура будет создана по шаблону.

    4. Должности (предпросмотр)

    Ниже — все типовые должности из глобального каталога с привязкой к типу подразделения (код справа: ADM, HR, SALES и т.д.). При запуске onboarding для каждой такой связки будет создана штатная позиция на соответствующем узле оргструктуры — по той же логике, что кнопка «Развернуть типовую оргструктуру» в карточке клиента.

      5. Администратор организации

      Ввод представителя клиента

      Это первый пользователь создаваемой организации (клиента), а не «общий администратор всей платформы». Уполномоченный представитель клиента: будет создан сотрудник в этой организации и учётная запись с указанным логином (логин должен быть уникален в системе). Дальше этот пользователь работает с данными той организации, которую вы задали на шаге 2.

      6. Аккаунты

      Будет создана учётная запись для сотрудника с шага 5 и назначена роль admin в системе ролей. Это не «суперпользователь платформы», а роль доступа, привязанная к этому клиенту через сотрудника: администрирование данных выбранной организации.

      7. Подтверждение

      Шаблон (например, default) — готовый сценарий развёртывания типовой оргструктуры из справочников; отдельная сущность «шаблон организации» не копируется — создаётся сама организация по этому шаблону.

      Нажатие любой из кнопок ниже запускает предварительные проверки готовности введённых данных к развёртыванию (код клиента, шаблон, уникальность логина и т.д.). Запустить Dry-Run — только эти проверки, без записи в базу: оргструктура для клиента не создаётся. Создать организацию — те же проверки и затем развёртывание структуры для клиента: запись клиента, подразделений, должностей, сотрудника и учётной записи администратора. После нажатия откроется шаг 8 с ходом выполнения.

      8. Прогресс и результат

      Dry Run — это проверка сценария без внесения изменений в систему.

      Ниже — статус запуска и список шагов. Сразу после нажатия кнопки на шаге 7 здесь появится сообщение о том, что идёт проверка или развёртывание. Для Dry-Run все шаги затем помечаются как пропущенные: данных в базе нет — это нормально. Для успешного создания организации появится идентификатор клиента и кнопки перехода внизу.
